Yollgo 商品被动采集助手 v1.0.0
适用：在已登录且有权访问的 https://app.yollgo.com/ 页面使用。
监听范围固定为 POST https://ssl.freex.es/api/articulos/6085。
交付：yollgo-collector.user.js、使用说明、自动测试报告、面板截图。

一、安装与首次验收（先只测当前类目）

1. 在 Chrome / Edge / Firefox 安装官方 Tampermonkey 扩展：
   https://www.tampermonkey.net/
2. 点击扩展图标 → 管理面板 → 新建脚本。
3. 用文本编辑器打开 yollgo-collector.user.js，复制全部内容（包括开头元数据），
   覆盖新建脚本的默认内容，按 Ctrl+S 保存。只启用一个副本。
   也可在管理面板的“实用工具 / 从文件导入”选择此 .user.js 文件。
4. 按浏览器/扩展提示允许用户脚本运行，并授予 app.yollgo.com 的站点访问权限。
   部分 Chromium 版本需要在扩展详情页开启“允许用户脚本”，旧版本可能要求开发者模式。
   以浏览器当前提示及 Tampermonkey 官方 FAQ 为准：
   https://www.tampermonkey.net/faq.php
5. 登录 app.yollgo.com。安装后完整刷新页面一次，让 document-start 监听生效。
   不要向脚本输入账号密码、Cookie、Authorization、API Key 或签名。
6. 右下角出现面板并显示“监听已就绪”后，手动打开店铺 6085 的类目 004。
   若页面已缓存该类目，切换到另一个可访问类目再切回，或完整刷新。
7. 出现“已保存本次 … 件商品”，商品计数应大于 0。
8. 点击“导出 JSON”，在浏览器下载目录打开 JSON，确认：
   - products 为数组，artId 与网页商品对应；
   - sources.muluid / submuluid 与请求类目一致（004 的前导零应保留）；
   - namecn/namees/precio 等与页面或开发者工具“响应”中的商品字段一致；
   - raw 保留该商品最后一次捕获的业务字段；
   - 无响应外围对象、请求头、Cookie 或其他认证字段。
9. 再导出 CSV，确认有表头且商品数与 JSON 一致。
   CSV 用 UTF-8 BOM、标准引号和 CRLF，嵌套字段用 JSON 字符串。
   Excel 导入时将 artId、usercode、bianhao、类目 ID 设为文本，避免丢失前导零。
   可能被 Excel 当成公式的文本加前置单引号；JSON 保留原业务文本。

完成以上步骤后，再进行下面的多类目与图片验收。

二、日常采集与多类目累积

- 手动切换约 26 个类目；每个类目都等网页正常加载完成后检查面板。
- 如网页分页或滚动加载，手动翻页、滚动，脚本只收集实际返回的列表。
- 不自动枚举类目、不批量发送商品请求、不触发支付、下单或业务按钮。
- 全部记录只按 artId 去重。同一商品重复返回时更新最新字段与 lastSeen，
  firstSeen 保留，所有不同的类目来源保留。重复命中表示累计重复次数，
  包括同一响应内重复，不是“重复商品的种数”。
- “最近捕获类目”指最近发起且已捕获的请求所携带的类目参数；
  它不是对网站当前高亮菜单的猜测。乱序响应也按请求先后维护这一显示。
- 若网页把 Request 对象直接传给 fetch，脚本不读取或复制其请求正文；
  此时 sources.muluid/submuluid 可能为 null，商品 mulUID 仍单独保留。
  类目统计会尽量采用 productMulUID；未知类目保持未知，不借用上次类目。
- IndexedDB 保存在当前浏览器配置的 app.yollgo.com 站点存储内。
  刷新、关闭再打开会恢复商品与暂停状态；无痕窗口或清理站点数据可能丢失进度。
- 用同一个浏览器配置采集。Web Locks 保证同一站点只有一个采集写入标签页；
  其他标签页显示只读，导出会读取数据库最新快照，面板计数刷新后更新。
  关闭原采集页后，刷新只读页即可接管。若浏览器不支持 Web Locks，保持只读。
- 类目统计是已见商品数；商品可属于多个类目，因此类目合计可大于总商品数。
  脚本无法证明网站全部商品都已返回，约 26 个类目也不会被当作完整性证明。

三、暂停、恢复、清空与备份

- 暂停采集：立即停止接受新捕获任务，忽略暂停前尚未处理的旧响应。
  已进入本地数据库提交阶段的记录可能完成保存；不会删除已保存商品。
  网站正常请求继续运行。暂停状态跨刷新保存，也停止后续图片下载任务。
- 恢复采集：只收集恢复后的正常请求。手动切换类目让网页重新请求商品。
- 清空本地数据：有确认框，只删除本脚本的 products 和计数，不动网站业务数据。
  清空后维持暂停，需点击恢复后继续。进行图片下载时先停止并等本轮结束。
- 导出备份：JSON 中含 schema、shopid、exportedAt、stats、products，
  可用于恢复。普通商品 JSON 也可恢复，但不含统计计数。
- 恢复备份：选择本脚本导出的 JSON 并确认，按 artId 合并到现有记录。
  同 ID 的导入商品字段替换当前字段，原有和备份类目来源合并；建议先导出当前备份。
  空库导入完整备份会恢复统计计数，非空库合并保留现有计数。
  导入后保持暂停；未在现有库验证过的图片链接会重新等待网页证据，
  避免任意备份注入下载目标。最大导入文件 100 MB。
- 不要把含认证信息的 HAR、整个 API 外围对象或请求详情作为备份导入。

四、图片关联规则（宁可待匹配）

脚本不拼接 CDN 路径，不请求 imageHash 推测地址。仅在以下证据成立时关联：
1. 商品原始字段中明确的图片 URL，与网页实际请求的图片资源 URL 完全一致；
2. 网页已成功显示的 img 带 data-art-id / data-artid，或最近的此类容器
   仅含一个 img，且标识对应已采集的 artId；
3. imageHash 是至少 8 字符的标记，且在已采集商品中唯一，
   它恰好等于实际图片 URL 的完整路径片段或去扩展名后的文件名。
   这是对已观察 URL 的匹配，不是构造或请求一个新地址。

- 同一 URL 同时指向多个商品时，取消关联，保留待匹配。
- 只按名称、列表顺序、相似文本、缩略图片形状不做关联。
- 带 query、fragment、用户名或密码的 URL 一律不记录，也不剥去参数猜一个新地址。
  即便 query 实际只是尺寸参数，也采用这一保守限制，避免收录签名与令牌。
- 目前仅覆盖 img 与浏览器 initiatorType=img 的资源，不提取 CSS 背景图、canvas、
  blob/data 图片或框架私有状态。最多缓存 6000 个无查询参数的观察 URL。
  商品本身不受这个图片缓存上限影响；大量图片可分批浏览、刷新后再匹配。
- images 保存 url、evidence、observedAt、resolution；imageStatus 为 matched 或 pending。
- 实际网站的 DOM 图片标识尚未现场确认。若真实页面使用其他明确 artId 属性，
  可在脚本顶部 IMAGE_ID_ATTRIBUTES 追加经验证的属性名。不要加入通用 data-id。
- 先浏览商品并滚动使懒加载图片显示，再点“重新匹配图片”。无法可靠关联仍为待匹配。

五、授权后的图片下载

1. 展开“图片下载与数据管理”。
2. 确认自己已获得相应图片使用和下载授权，勾选授权复选框。
3. 点击“下载匹配图片”并确认数量。脚本依次 GET 已匹配的真实 URL，
   使用 credentials:omit、no-referrer、禁止跟随重定向，不增加认证头。
4. 只接受 JPEG/PNG/WebP/GIF/AVIF/BMP，保留响应原始字节，不重压缩、不放大。
   文件名包含 artId；每张间隔约 750 ms，每个请求超时 15 秒。
5. 这意味着下载网页已观察资源的原始文件；不能保证是源站最高分辨率母图。
   如果网页只加载缩略图，下载的也是该缩略图。不会将缩略图地址改成推测的原图地址。
6. 浏览器可能提示允许多文件下载。面板“交给浏览器”不代表文件已成功落盘，
   请检查下载目录。停止按钮阻止后续保存；正在请求的资源可能仍等待超时或完成。
7. CDN 没有开放 CORS、要求认证/Referer、发生重定向或格式不支持时会失败并跳过。
   本版本不使用跨域特权接口绕过这些限制；可依网站正常下载功能获取已获授权图片。

六、数据与隐私边界

- @grant none，@sandbox raw，document-start，在页面上下文包装 Fetch/XHR。
- 将原函数 this 与原参数原样传回，Fetch 返回原 Promise，XHR 返回值保持原样；
  Fetch 仅克隆响应读取 JSON，XHR 只读已完成响应。不改请求头、正文、方法或目标。
- 仅投影 shopid、muluid、submuluid 三个业务参数；不读取请求头、Cookie、
  localStorage 内的认证项，不复制 Request 流，不保存原始请求正文或请求 URL。
- 从唯一 articulo_lists 提取商品行，不保存 API 响应外围对象。
- raw 表示经过隐私过滤的最新商品原始字段，不是未经处理的完整响应：
  常见认证键（包括嵌套 token、signature、api_key、Authorization 等）被移除，
  明显的 Bearer/JWT/凭据文本被替换，含参数的 URL 被省略。
  因此含认证信息的字段不会以“保留原始字段”为由原样导出。
- 不记录调试响应或请求日志，不向第三方上传商品与图片，没有远程依赖。
- 面板使用 Shadow DOM 隔离样式，商品文本不作为 HTML 插入。
- IndexedDB 属于站点本地存储，同源页面脚本可访问，不是加密保险库。
  备份是本地下载文件，请自行妥善保存并按授权范围使用。
- 本版本监听当前顶层网页的主线程 Fetch/XHR。iframe、Worker 内请求、
  注入前发生的请求、网页缓存但未重新返回的商品不会自动补采。

七、常见故障

面板完全不出现：
  确认网址为 https://app.yollgo.com/；检查脚本已保存、启用且元数据未丢失；
  开启浏览器要求的用户脚本权限；完整刷新。不要同时开两个本脚本副本。

面板出现但商品一直为 0：
  先看是否暂停、只读或有本地存储错误；手动切换类目重新请求。
  开发者工具 → Network → 搜索 articulos，确认自然发起的请求是 POST、
  域名 ssl.freex.es、路径 /api/articulos/6085，且响应为成功 JSON。
  只在本机看响应结构，不复制或发送认证头、完整请求体或 HAR。
  若请求在 Worker/iframe 内，或网页后续覆盖了 Fetch/XHR，当前版本可能捕获不到。
  不使用复制认证凭据、重放签名或放宽权限的方式排查。

提示“响应未找到唯一 articulo_lists 数组”：
  返回可能是业务错误、登录过期、结构变化或多个同名列表。
  用网站正常流程重新登录；确认响应中实际商品数组位置。歧义时脚本不猜测。

最近捕获类目显示未知：
  网站可能传入 Request 对象、二进制或其他未支持正文。
  商品 mulUID 会保留；没有可靠类目参数时不会借用旧请求参数。

图片全部待匹配：
  先滚动加载图片；点重新匹配；检查 URL 是否带参数、hash 是否唯一、
  是否有明确 data-art-id/data-artid；没有可靠证据就保留待匹配。

图片下载失败：
  检查 CDN 的正常跨域许可、图片格式、是否重定向，及浏览器多文件下载提示。
  不通过发送认证凭据或关闭访问控制解决。

刷新后没有数据 / 本地存储失败：
  是否换了浏览器配置、无痕窗口、站点域名，或清理了网站存储？
  检查磁盘/站点存储空间，先导出可读取的数据库记录备份。
  存储错误时脚本停止写入，并显示错误；修复后刷新，或备份后清空本脚本存储。
  存储完全打不开时无法恢复尚未落库的数据，不把内存数据伪装成已持久保存。

八、建议的完整现场验收

□ 004 类目单次捕获，JSON/CSV 下载内容核对通过。
□ 同一类目重复打开，总商品数不变，重复命中增长。
□ 切换第二类目，新增商品追加，重复商品保留两类目来源。
□ 刷新后商品仍在；暂停后切换类目不增长；恢复后新请求可增长。
□ 展开类目统计，逐一浏览约 26 个类目并检查分页，不把列表首屏当成全部。
□ 图片资源与 artId 对照；不明确、冲突及带参数链接保持待匹配。
□ 授权后下载少量图片，核对 artId、内容和原资源字节。
□ 先备份，再清空，再恢复；商品、来源、时间可恢复，图片待重新验证。
□ 网站原有浏览、查询行为正常，Network 中没有脚本额外发出的商品 POST。
